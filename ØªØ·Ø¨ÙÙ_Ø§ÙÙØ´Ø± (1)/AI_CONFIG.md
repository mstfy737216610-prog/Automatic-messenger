# إعداد الذكاء الاصطناعي والتعلّم

## الاتصال

يستخدم النظام مسارين متوافقين مع OpenAI:

```text
GET  {AI_BASE_URL}/models
POST {AI_BASE_URL}/chat/completions
```

المفتاح يُقرأ من `AI_API_KEY` في `.env` أو البيئة، ولا يظهر في الواجهة ولا يُحفظ في قاعدة البيانات أو النسخ الاحتياطية. لا تضع المفتاح في `src/` أو `config/selectors.yaml` أو Git.

الإعداد الافتراضي:

```dotenv
AI_BASE_URL=https://api.hcnsec.cn/v1
AI_MODEL=auto
AI_TIMEOUT_SECONDS=60
AI_MAX_RETRIES=2
```

## نتيجة الاختبار الفعلي

بتاريخ **2026-10-28** أثناء بناء هذا المشروع:

- نجح `GET /v1/models` وأعاد 19 معرفًا.
- نجح طلب محادثة صغير باستخدام `auto` خلال نحو **1.58 ثانية**، وأعاد `{"ok":true}`؛ كان النموذج المعلن في الرد `agnes-3.0-flash`.
- انتهى اختبارا `DeepSeek-V4.1-Flash` و`glm-5.3-flash` بمهلة تقارب 75 ثانية في تلك التجربة. هذا يصف نتيجة الاختبار وقتها، وليس حكمًا دائمًا على النموذجين.

لذلك `auto` هو الافتراضي. عند تغيير المزوّد أو النموذج استخدم **اختبار الرد** من صفحة المساعد؛ نجاح قائمة النماذج وحده لا يثبت نجاح المحادثة.

## مخطط قرار الفلترة

يطلب النظام كائن JSON واحدًا:

```json
{
  "decision": "publish | ignore | review",
  "reason": "سبب عربي موجز",
  "category": "university | student_help | advertisement | personal | entertainment | …",
  "confidence": 0.0,
  "important": false,
  "replace_phone": false,
  "cleaned_text": null
}
```

يتحقق Pydantic من الحقول والأنواع ونطاق الثقة. JSON داخل code fence مقبول، أما الرد غير الصالح أو غير المطابق فيُعامل كفشل AI.

### سياسة الفشل

- انقطاع الشبكة أو المهلة أو رفض المزوّد أو JSON غير صالح يحول المنشور إلى `pending_review` مع سبب الخطأ.
- لا يتحول الفشل إلى `publish` أو `ignore`.
- الأخطاء المؤقتة فقط تُعاد محاولتها وفق `AI_MAX_RETRIES` مع backoff قصير.
- النشر التلقائي يحتاج قرار `publish` وثقة لا تقل عن `settings.auto_confidence`، الافتراضية `0.88`، مع تعطيل المراجعة وتفعيل النشر صراحة.

## التعلّم من التاريخ — لا Fine-tuning

يحفظ `bot_memory.db`:

1. التعليمات العامة والخاصة بالحساب من صفحة المساعد.
2. قرارات المراجعة وأسباب الرفض والتعليقات.
3. قرارات التجاهل الآلية وأسبابها.
4. ملف النمط واللهجة والموضوعات عند توليده.

في كل تصنيف يُرسل النظام كسياق:

- حتى 30 تعليمة نشطة عامة أو خاصة.
- حتى 15 ملاحظة مراجعة حديثة للحساب.
- اللهجة والملاحظات الأسلوبية من ملف النمط.

هذا **History-based Rule Learning**: تتغير التعليمات والسياق، ولا تتغير أوزان النموذج ولا يُنشأ نموذج مدرّب محليًا.

## احتواء التعليمات داخل المحتوى

نص المنشور وOCR والرابط يوضعان كبيانات غير موثوقة داخل رسالة المستخدم، مع تعليمة صريحة بعدم تنفيذ أي أوامر داخلها. لا تُمنح محتويات المنشور صلاحية تعديل قواعد المالك. رغم ذلك تبقى المراجعة البشرية ضرورية؛ لا يوجد Prompt يضمن منع كل حقن تعليمات.

## استبدال الهاتف والمعرف

- لا يطلب النظام من النموذج استبدال رقم الهاتف.
- بعد التصنيف، إذا كان `replace_phone=true` أو الفئة `student_help`، يستبدل كود Python الأرقام المطابقة برقم الحساب.
- يدعم التعبير الأرقام العربية واللاتينية والمسافات والرموز الشائعة، ويقبل الرقم عندما يكون مجموع أرقامه بين 7 و15.
- لا يُستبدل الرقم إذا كان `phone_replacement` فارغًا.
- استبدال `@المصدر` بمعرفك مستقل ويحدث فقط عند تفعيل `replace_username` ووجود اسم مستخدم للحساب.

## بناء ملف النمط

زر **تحليل النمط** يرسل حتى 25 عينة نصية قصيرة من سجل الحساب ويطلب `dialect` و`topics` و`style_notes` و`publishing_guidelines`. يحفظ الناتج في جدول `profiles` وفي `data/accounts/{id}/profile.json`. لا يُستخدم لاستنتاج معلومات شخصية، ويحتاج عينات كافية واتصال AI ناجحًا.
