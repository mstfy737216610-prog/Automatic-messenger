# مرسال

نظام محلي عربي لمراقبة حسابات التواصل، وفلترة المحتوى، ومعالجة الوسائط، ومراجعته، ثم تجهيزه للنشر على حسابات متعددة. يعمل على Termux/Android وعلى Python 3.11+ في الأنظمة المكتبية، ولا يستخدم واجهات النشر الرسمية لـ X أو TikTok أو Instagram أو Telegram.

## حدود مهمة قبل التشغيل

- **الوضع الافتراضي لا ينشر:** `DRY_RUN=true` و`PUBLISHING_ENABLED=false`. الاعتماد في هذا الوضع ينتج منشورًا بحالة «جاهز — لم يُرسل».
- **المراجعة البشرية مطلوبة افتراضيًا:** لا يوجد نشر تلقائي إلا بعد تعطيل المراجعة وتفعيل الخيار صراحة، وتحقق قرار «نشر» وعتبة الثقة.
- **لا يوجد ضمان ضد الحظر أو طلبات التحقق:** استخدم حساباتك، ووتيرة معتدلة، وبروكسي ثابتًا لكل حساب، وراجع شروط كل منصة وحقوق إعادة استخدام المحتوى.
- **محددات المواقع قابلة للتغيير:** يلزم اختبار الجلسات والمحددات على الحسابات الحقيقية قبل أي نشر. راجع [SELECTORS.md](SELECTORS.md).
- **النتيجة الغامضة لا تُعاد تلقائيًا:** إذا لم يظهر تأكيد نجاح موثوق تصبح الحالة `publish_unknown`؛ افتح المنصة وتأكد يدويًا بدل تكرار المنشور.
- **التعلّم هنا سياق وقواعد محفوظة، وليس تدريب نموذج:** التعليمات والمراجعات وأسباب الرفض تُحفظ في SQLite وتُرسل كسياق في التصنيفات اللاحقة.

## المكونات

- FastAPI + SQLite (`data/bot_memory.db`) + طابور مهام واحد متسلسل.
- Playwright مع Chromium المثبت من النظام، وجلسة `storage_state` منفصلة لكل حساب.
- `twscrape` لقراءة X عند توفر جلسة مناسبة، وقارئ متصفح بديل قابل للضبط.
- `yt-dlp` لتنزيل الفيديو، وFFmpeg للعلامة المائية و`delogo` والتعديل اللوني البسيط.
- Pillow مع خط Tajawal ودعم RAQM لإخراج العربية واللاتينية والرموز بوضوح، وTesseract بـ`ara+eng` لاستخراج النص.
- مزوّد OpenAI-compatible للفلترة واختبار النماذج، مع تحقق Pydantic من JSON.
- واجهة React عربية RTL للهاتف وسطح المكتب.
- منع تكرار مستقل عن سجل المنشورات؛ حذف السجلات القديمة لا يحذف بصمات `dedup`.

## التثبيت على Termux

1. ثبّت Termux من مصدر موثوق ومحدّث، ثم انسخ المشروع إلى التخزين الداخلي، مثل:

   ```sh
   ~/mirsal
   ```

2. من مجلد المشروع نفّذ:

   ```sh
   bash install_termux.sh
   ```

   السكربت يثبت Python وChromium وFFmpeg وTesseract، وينشئ بيئة `.venv`، ويثبت متطلبات Python. لا ينفّذ `playwright install chromium`؛ يستخدم متصفح Termux. إذا لم توجد بيانات OCR العربية ينزّل `ara.traineddata` من مشروع Tesseract الرسمي.

3. افتح `.env` وضع مفتاح الاختبار في `AI_API_KEY` دون مشاركته:

   ```sh
   cp .env.example .env   # فقط إذا لم ينشئه التثبيت مسبقًا
   nano .env
   chmod 600 .env
   ```

4. شغّل النظام:

   ```sh
   bash start.sh
   ```

5. افتح على الهاتف:

   ```text
   http://127.0.0.1:8000
   ```

الواجهة المبنية داخل `dist/`، لذلك لا يحتاج التشغيل المعتاد إلى Node.js. عند تعديل `src/` نفّذ `bash build_frontend.sh`.

## أول إعداد آمن

1. من **الحسابات** أنشئ حساب وجهة واحدًا، واتركه متوقفًا في البداية.
2. ارفع Cookies بصيغة Playwright storage state أو قائمة Cookies، ثم اضغط **فحص الجلسة**. التفاصيل في [ACCOUNTS_SETUP.md](ACCOUNTS_SETUP.md).
3. أضف مصدرًا واحدًا فقط، وارفع شعارك وقالبك، وأنشئ معاينة عربية.
4. من **المساعد** اختبر النموذج، وأضف قاعدة واضحة واحدة.
5. نفّذ **فحص الآن**، ثم راجع النص الأصلي وOCR والصورة المعالجة وقرار الفلترة.
6. اعتمد منشورًا في وضع الاختبار وتأكد أن حالته «جاهز — لم يُرسل» وأن النتيجة صحيحة.
7. كرر الاختبار على عدة أنواع محتوى قبل التفكير في النشر الفعلي.

## تشغيل النشر الفعلي لاحقًا

لا تفعل ذلك قبل اختبار الجلسة والمحددات ومسار النشر يدويًا. عند الاستعداد:

```dotenv
DRY_RUN=false
PUBLISHING_ENABLED=true
```

ثم أعد التشغيل. يبقى النشر التلقائي متوقفًا ما دامت **المراجعة البشرية مطلقة** أو `auto_publish=false`. إبقاء `DRY_RUN=true` وحده كافٍ لمنع الإرسال حتى مع تفعيل الخيارات الأخرى.

## أوامر الإدارة

```sh
python -m automation doctor                 # فحص البيئة دون كشف الأسرار
python -m automation serve                  # الواجهة والعامل
python -m automation models                 # قائمة النماذج من المزوّد
python -m automation monitor ACCOUNT_ID     # فحص حساب مرة واحدة
python -m automation login ACCOUNT_ID       # متصفح مرئي؛ يحتاج Termux:X11
python -m automation import-cookies ACCOUNT_ID session.json
python -m automation backup
python -m automation cleanup
python -m automation archive-account ACCOUNT_ID
```

على Termux استخدم `bash backup.sh` للنسخ المضغوط. النسخة تشمل قاعدة البيانات والجلسات والملفات الشخصية والشعارات والقوالب و`selectors.yaml`، وتستبعد مفتاح AI والوسائط المنزلة وملفات Cookies المؤقتة الخاصة بـ`yt-dlp`.

## التخزين والعزل

```text
data/
├── bot_memory.db
├── accounts/ACCOUNT_ID/
│   ├── session-PLATFORM.json
│   ├── x-twscrape.db
│   ├── profile.json
│   ├── assets/
│   └── media/
├── backups/
├── exports/
└── tmp/
```

لكل حساب مصادر وجلسة وبروكسي وذاكرة تعليمات وملف نمط وقوالب مستقلة. مجلد `data/` وملف `.env` مستبعدان من Git والحزمة العامة. احتفظ بنسخك الاحتياطية مشفرة أو في مكان خاص؛ الجلسات تمنح الوصول إلى الحساب.

## التشغيل المكتبي أو Docker

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
npm ci && npm run build
python -m automation serve
```

أو باستخدام Docker مع مجلد بيانات ثابت:

```sh
docker build -t mirsal .
docker run --rm -p 8000:8000 -v mirsal-data:/app/data mirsal
```

مرّر `AI_API_KEY` كمتغير بيئة عند الحاجة، ولا تضعه داخل صورة Docker.

### نتائج التحقق في بيئة التطوير

- نجحت اختبارات Python الـ21، وفحص Ruff، وفحص TypeScript/ESLint، وبناء الواجهة، وفحص صياغة سكربتات التشغيل.
- أظهر `npm audit` صفر ثغرات معروفة في الاعتماديات وقت الفحص.
- اجتازت الصفحات الست فحصًا فعليًا على الهاتف وسطح المكتب دون أخطاء Console أو استجابات HTTP فاشلة أو تمرير أفقي، كما تم فحص المراجعة المعبأة ونافذة الحساب وحالتي التحميل والخطأ وإعادة المحاولة على الهاتف.
- لم يتوفر Docker في بيئة التطوير، لذلك لم يُبنَ ملف Docker فعليًا؛ أوامره موثقة ولم يُدَّع اختبارها.

اختبارات النظام لا تتصل بحسابات التواصل الحقيقية. اختبار المزوّد الحقيقي منفصل ويحتاج مفتاحًا صالحًا. لا يمكن إثبات صلاحية محددات النشر أو جلسة حساب دون حساب فعلي وجلسة المستخدم. كذلك لم يُختبر التثبيت على جهاز Termux حقيقي ضمن هذه البيئة؛ يلزم تنفيذ `install_termux.sh` و`doctor` على الجهاز المستهدف قبل الاعتماد التشغيلي.
