# إعداد الحسابات والمصادر والجلسات

## مفهوم الحساب في مرسال

كل سجل في صفحة **الحسابات** يمثل وجهة نشر مستقلة. يمكن أن يكون لديك مثلًا حساب X للأخبار وحساب Instagram للمحتوى البصري وقناة Telegram للتنبيهات. لكل واحد:

- مصادر مستقلة.
- جلسة Chromium مستقلة داخل `data/accounts/{id}/`.
- بروكسي ثابت مستقل.
- تعليمات ومراجعات وملف نمط مستقل.
- شعار وقالب وإعدادات مراجعة وتأخير مستقلة.

ابدأ بحساب واحد ومصدر واحد حتى تثبت السلسلة كاملة في وضع الاختبار.

## الطريقة الموصى بها: استيراد الجلسة

1. سجّل الدخول يدويًا إلى حسابك في متصفح موثوق وأكمل أي تحقق تطلبه المنصة.
2. صدّر الجلسة بصيغة **Playwright storage state**، أو قائمة Cookies JSON للموقع نفسه. لا ترسل الملف لأي شخص ولا ترفعه إلى خدمة خارجية.
3. من صفحة الحساب اضغط **استيراد Cookies** واختر الملف.
4. اضغط **فحص الجلسة**. النتائج:
   - `valid`: ظهر مؤشر الجلسة النشطة.
   - `missing`: لا يوجد ملف جلسة.
   - `expired`: ظهر مؤشر طلب تسجيل الدخول.
   - `unknown`: فُتحت الصفحة لكن المؤشر لم يظهر؛ راجع المحددات ولا تعتبرها جلسة ناجحة.
   - `error`: تعذّر تشغيل المتصفح أو الاتصال.

يُحفظ الملف بصلاحية `600` قدر الإمكان باسم `session-{platform}.json`. استيراد جلسة جديدة يستبدل السابقة لهذا الحساب والمنصة.

### صيغة Playwright storage state

```json
{
  "cookies": [
    {
      "name": "session_cookie",
      "value": "SECRET",
      "domain": ".example.com",
      "path": "/",
      "expires": -1,
      "httpOnly": true,
      "secure": true,
      "sameSite": "Lax"
    }
  ],
  "origins": []
}
```

تُقبل أيضًا قائمة Cookies مباشرة (`[ {...}, {...} ]`) وتتحول إلى `origins: []`. بعض المنصات تعتمد على Local Storage إضافة إلى Cookies؛ لذلك تكون storage state الكاملة أفضل من قائمة Cookies عند توفرها.

## تسجيل الدخول اليدوي من الطرفية

```sh
python -m automation login ACCOUNT_ID
```

يفتح Chromium مرئيًا. سجّل الدخول بنفسك، ثم عد إلى الطرفية واضغط Enter ليحفظ الحالة. على Termux تحتاج بيئة عرض مثل **Termux:X11**؛ إن لم تتوفر استخدم الاستيراد من الواجهة بدلًا من هذا الأمر. لا يطلب النظام كلمة مرور حسابك داخل الواجهة.

## إضافة المصادر

لكل مصدر:

- المنصة: X أو TikTok أو Instagram.
- المعرف دون `@`.
- رابط الصفحة العامة الكامل `https://…`.
- حالة التفعيل.

يمكن تعطيل مصدر دون حذف سجله. تكرار المصدر نفسه للحساب ممنوع بقيد قاعدة البيانات. أخطاء مصدر لا تسقط بقية مصادر الحساب؛ تظهر رسالة الخطأ بجوار المصدر وفي سجل النشاط.

### X

عند وجود جلسة محفوظة ووضع القراءة `auto` يحاول النظام استخدام `twscrape` بقاعدة مستقلة `x-twscrape.db` للحساب. عند عدم ملاءمته يستخدم قارئ المتصفح. `twscrape` هنا للقراءة فقط، وليس للنشر.

### TikTok وInstagram وقارئ المتصفح

يستخدم `BrowserReader` محددات `config/selectors.yaml` ويمكن تجاوزها لكل مصدر عبر `source.config`. `yt-dlp` يستخدم لتنزيل الفيديو عند توفر رابط مناسب، مع الجلسة والبروكسي نفسيهما.

## فحص وتشغيل الحساب

1. لا تفعّل الحساب قبل نجاح استيراد الجلسة وإضافة المصدر.
2. اضغط **فحص الآن** وانتظر الطابور.
3. راجع صفحة **النشاط** عند ظهور خطأ مصدر.
4. راجع النتائج يدويًا واختبر المعالجة والقالب.
5. فعّل الحساب للجدولة الدورية فقط بعد استقرار الفحص اليدوي.

`SCHEDULER_ENABLED=true` يشغّل الجدولة، لكنها لا تفحص إلا الحسابات التي `enabled=true`. الفاصل الافتراضي 900 ثانية، والحد الأدنى المقبول 60 ثانية. الفاصل القصير لا يعني موثوقية أعلى، وقد يزيد طلبات التحقق.

## النشر على كل منصة

- **X:** يدعم النص والوسائط وفق خطوات المحددات.
- **Instagram وTikTok:** يشترط النظام وجود ملف وسائط قبل بدء النشر.
- **Telegram:** يلزم `telegram_target_url` لرابط المحادثة في Telegram Web. لا يوجد مؤشر نجاح موثوق افتراضيًا؛ لذلك تكون النتيجة غالبًا `publish_unknown` حتى تتحقق يدويًا.

قبل النشر الفعلي اختبر الخطوات على حسابك، وحدّث المحددات إذا تغيّرت المنصة. لا تعِد محاولة منشور `publish_unknown` تلقائيًا.

## حذف حساب أو أرشفته

- `python -m automation archive-account ACCOUNT_ID` ينشئ أرشيفًا دون الوسائط.
- أضف `--include-media` إذا احتجت الوسائط داخل الأرشيف.
- حذف الحساب من الواجهة ينشئ أرشيف أمان أولًا ثم يحذف بياناته. راجع ملفات `data/exports/` واحتفظ بها بأمان.
